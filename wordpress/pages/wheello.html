// 01 — CONTEXTE

Le besoin.

Habitat Insertion est une association qui met des véhicules à disposition de ses salariés. Il fallait un outil unique pour savoir quel véhicule est disponible, qui le réserve, quand il part, quand il revient et dans quel état.

Notre équipe a conçu Wheello de A à Z : une interface d'administration web pour les responsables, une application mobile pour les salariés sur le terrain, et une API qui fait communiquer les deux.

// 02 — ARCHITECTURE

Le système.

Wheello repose sur trois briques. L'application mobile ne parle jamais directement à la base de données : elle passe par l'API, qui vérifie le jeton de connexion avant de répondre.

// 03 — INTERFACES

Deux applications, un système.

POUR LES ADMINISTRATEURS

Le back-office web

Symfony · PHP · Doctrine

Les responsables gèrent toute la flotte depuis leur navigateur : véhicules, utilisateurs, sites, réservations, constats et bilans. Deux niveaux d'accès existent : administrateur et super-administrateur.

  • Planning et disponibilités des véhicules
  • Gestion des utilisateurs, sites et pôles
  • Bilans kilométriques avec filtres
  • Archivage et anonymisation (RGPD)

POUR LES SALARIÉS SUR LE TERRAIN

L'application mobile

Flutter · Dart

Depuis leur téléphone, les salariés consultent les véhicules, réservent, déclarent un départ ou un retour et signalent un problème, sans passer par un ordinateur.

  • Consultation des véhicules disponibles
  • Réservation et modification de période
  • Déclaration de départ et de retour
  • Signalement d'un problème sur un véhicule

Tests unitaires & golden tests

J'ai écrit des tests pour l'application Flutter. Les tests unitaires vérifient la logique de l'application. Les golden tests comparent le rendu d'un écran à une image de référence : si l'affichage change sans le vouloir, le test échoue.

  1. Rendu actuel
  2. Image de référence
  3. Comparaison
  4. OK / ÉCHEC

Ce que fait Wheello.
